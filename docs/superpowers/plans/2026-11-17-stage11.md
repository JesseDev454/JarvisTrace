# Stage 11 hybrid window retrieval implementation plan

**Goal:** Read-only hybrid retrieval over compatible CLIP image vectors and
provenance-qualified existing MiniLM descriptions, with explainable window ranks.

**Spec:** Master brief Stage 11; `docs/ARCHITECTURE.md`; Stage 10 visual baseline.

**Architecture:** Separate visual/text query encoders; approved-source SQL joins;
source-hash binding to immutable visual metadata; deterministic fixed video windows;
one vote per channel/window; reciprocal rank fusion. No schema changes or new AI
captions, and no direct comparison of 512-d and 384-d vectors.

## Constraints and review focus

- Preserve existing records, source files, model versions and unrelated local edits.
- Text eligible only through a matching manual frame label or explicit Stage 6
  temporal index entry. Exclude seeds, arbitrary scene inserts and unreviewed captions.
- Match description/model/video/camera/time provenance. Verify legacy text source
  bindings against immutable visual metadata and actual current source hashes.
- Apply camera/video/time predicates in both branches. End bounds are exclusive;
  return windows clipped to requested bounds and retain original text-evidence ranges.
- Collapse repeated crop/frame/scene matches before assigning channel window ranks.
  Never merge recordings/cameras/source-content versions; return exact contributions.
- RRF parameters are configurable research defaults, not confidence probabilities.
- Existing single synthetic clip cannot show general hybrid superiority. Save raw
  CLIP/text/hybrid comparisons without inventing relevance ground truth or accuracy.
